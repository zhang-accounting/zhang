---
title: Setting Up S3 as a Data Source
description: A guide on using Amazon S3 or any S3-compatible object storage as the data source of Zhang Accounting.
---

## Introduction

Amazon S3 and S3-compatible object storages (MinIO, Cloudflare R2, Aliyun OSS, Tencent COS, Backblaze B2, etc.) are cheap, durable and widely available. Zhang Accounting can read and write your ledger files directly from a bucket, which makes it easy to run the server statelessly (e.g. in a container) while keeping your data in object storage.

## Configuration Requirements

| Parameter | Command Line Argument | Environment Variable | Required | Example Value | Remarks |
|-----------|-----------------------|----------------------|----------|---------------|---------|
| Data Source | source | ZHANG_DATA_SOURCE | Yes | `s3` | Identifies S3 as the data source. |
| Bucket | N/A | ZHANG_S3_BUCKET | Yes | `my-ledger` | The bucket where your ledger files are stored. |
| Root Directory | N/A | ZHANG_S3_ROOT | No | `/accounting` | The prefix inside the bucket where your ledger lives. Defaults to `/`. |
| Endpoint | N/A | ZHANG_S3_ENDPOINT | No | `https://<account_id>.r2.cloudflarestorage.com` | Required for S3-compatible services. Defaults to `https://s3.amazonaws.com`. |
| Region | N/A | ZHANG_S3_REGION | No | `us-east-1` | Falls back to `AWS_REGION`. A region is required by the signer, use `auto` for Cloudflare R2 and `us-east-1` for MinIO. |
| Access Key ID | N/A | ZHANG_S3_ACCESS_KEY_ID | No | `AKIA...` | Falls back to the standard AWS credential chain (`AWS_ACCESS_KEY_ID`, `~/.aws/credentials`, ...). |
| Secret Access Key | N/A | ZHANG_S3_SECRET_ACCESS_KEY | No | `your_secret` | Falls back to the standard AWS credential chain. |
| Session Token | N/A | ZHANG_S3_SESSION_TOKEN | No | `your_session_token` | Only needed for temporary credentials. |
| Virtual Host Style | N/A | ZHANG_S3_VIRTUAL_HOST_STYLE | No | `true` | Use `https://<bucket>.<endpoint>` instead of path style `https://<endpoint>/<bucket>`. Required by some providers like Aliyun OSS. |

The `path` argument of `zhang serve` is ignored for S3, the ledger root is controlled by `ZHANG_S3_ROOT`. The main file is still selected by `--endpoint` (default `main.zhang`).

## Step-by-Step Setup

1. **Create a bucket** and upload your ledger files (e.g. `main.zhang`) into it, optionally under a prefix such as `accounting/`.
2. **Create credentials** that are allowed to `GetObject`, `PutObject` and `ListBucket` on that bucket.
3. **Configure environment variables** and start Zhang Accounting:

```shell
ZHANG_DATA_SOURCE=s3 \
ZHANG_S3_BUCKET=my-ledger \
ZHANG_S3_ROOT=/accounting \
ZHANG_S3_REGION=us-east-1 \
ZHANG_S3_ACCESS_KEY_ID=your_access_key \
ZHANG_S3_SECRET_ACCESS_KEY=your_secret \
zhang serve /accounting --endpoint main.zhang
```

### Docker

```shell
docker run --name zhang -d -p 18000:8000 \
  -e ZHANG_DATA_SOURCE=s3 \
  -e ZHANG_S3_BUCKET=my-ledger \
  -e ZHANG_S3_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com \
  -e ZHANG_S3_REGION=auto \
  -e ZHANG_S3_ACCESS_KEY_ID=your_access_key \
  -e ZHANG_S3_SECRET_ACCESS_KEY=your_secret \
  kilerd/zhang:latest
```

## Troubleshooting

- **`region is missing`**: set `ZHANG_S3_REGION` (or `AWS_REGION`). For S3-compatible services that do not care about regions, `us-east-1` or `auto` usually works.
- **Access denied**: make sure the credentials have read, write and list permissions on the bucket and prefix.
- **Wrong files are loaded / nothing is found**: check `ZHANG_S3_ROOT` and `--endpoint`; the main file is read from `<ZHANG_S3_ROOT>/<endpoint>` inside the bucket.

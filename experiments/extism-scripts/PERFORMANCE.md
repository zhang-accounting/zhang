# 本机性能记录（2026-10-05）

环境：Apple M4，macOS 26.3，Extism 1.30.0，Python PDK 0.1.5，
Lua 5.4.8 + dkjson 2.11。沿用功能验证的两个 WASM 文件，未修改生产代码。
Rust 宿主与依赖均使用优化级别 2。执行命令：

```sh
cargo run --locked --manifest-path experiments/extism-scripts/Cargo.toml --features lua-exceptions --bin performance
```

完整测试退出码为 0，逐次验证了脚本返回值和真实 Router 的报表结果。
原始数值、样本量和分位数保存在 [PERFORMANCE.json](PERFORMANCE.json)。
这是本机顺序延迟测试，不是服务器吞吐量测试；运行期间耗时有明显波动。

## 运行结果

以下均为中位数，单位 ms。WASM 无缓存编译只有一个观察值。

| 工作 | Rust 直接执行 | Python / WASM | Lua / WASM |
| --- | ---: | ---: | ---: |
| 无缓存 WASM 编译 | — | 3,724 | 176 |
| 从已编译模块创建插件对象，不含首次实例化 | — | 1.08 | 0.16 |
| 首次执行空脚本，单次观察 | — | 17.18 | 1.31 |
| 同一实例重复执行空脚本 | — | 0.079 | 0.966 |
| 脚本调用一次真实 `zhang_now` | — | 0.431 | 1.780 |
| 脚本一次执行内调用 `zhang_now` 100 次 | — | 4.96 | 4.72 |
| 整数求和循环 100,000 次 | 0.117 | 64.62 | 6.46 |
| 1,000 笔交易的完整指令 JSON 往返，约 0.86 MB | 9.86 | 130 | 561 |
| 10,000 笔交易的完整指令 JSON 往返，约 8.63 MB | 133 | 2,089 | 9,172 |
| 10,000 笔交易的 BQL 汇总，复用插件实例 | 4.42 | 4.18 | 4.50 |
| 当前生产 Router 调用路径，同一条 BQL，每次创建插件 | — | 572 | 12.96 |

原生 JSON 基线是 Rust `serde_json::Value` 的解码与编码，不是完整账本处理。
整数循环的 Rust 基线用 `black_box` 保留逐次累加，不让编译器折叠成公式。
脚本循环返回 `{"sum": ...}`，测试每次检查结果 `5000050000`。

脚本重复调用排除了 Rust 侧请求编码和响应 JSON 解码的耗时，包含 Extism
输入/输出复制、脚本侧 JSON 解码/编码、源码编译和脚本执行。因此真实业务
端到端耗时还会包括宿主侧编解码、HTTP、网络等工作。

报表通过 Rust BQL 执行 `sum(number)`，得到 `Expenses:Food` 的精确金额
`123400.00`，只把汇总表返回脚本。复用实例的测试用独立的测试查询绑定访问
固定账本；生产 Router 测试调用真实 `RegisteredPlugin::execute_as_router`。
复用实例尚未在生产 Router 中实现。原生和脚本报表的几毫秒差异属于测量波动，
不能据此认为脚本比直接执行 Rust 快。

## 对迁移方案的含义

1. **先复用 WASM 编译结果。** 当前 `router.rs` 每个请求调用 `Plugin::new`，
   `RegisteredPlugin` 只保存 WASM 字节。Extism 已有 `CompiledPlugin` 和
   `Plugin::new_from_compiled`，可保留每次请求独立实例，同时避免反复加载/编译
   模块。实例对象创建之后仍有首次实际执行的初始化成本；正式接入还需正确
   绑定每次调用的宿主状态。
2. **用小请求和汇总结果作为插件边界。** 同一报表在复用实例时仍约 4–5 ms；
   但把完整账本传入并原样返回，即使没有业务计算，也会达到秒级。
   原型中的 JSON 指令流接口不适合作为所有业务插件的通用数据接口。
3. **计算原语与账务不变量保留 Rust，业务流程可以迁到脚本。** BQL、精确金额、
   库存/余额处理等能力通过较粗粒度的宿主接口开放。脚本承担报表组合、规则、
   导入映射和展示逻辑；性能敏感的插件也可以直接用 Rust 编译为 WASM。
4. **继续优化原型时，需要分别解决实例与编码成本。** Lua 当前每次调用都新建
   Lua state，并重新加载纯 Lua JSON 库；Python 复用解释器。
   缓存源码/字节码、改进 Lua JSON 编解码可能降低开销，但此次没有测这些优化。
   生产实例池还需要保持请求隔离，并正确切换账本和宿主调用上下文。

Lua 的大 JSON 测试只有 5 个计时样本，观察范围为 4.79–21.31 秒；Python 对应
范围为 1.34–2.92 秒。这些数字用于确认当前实现的瓶颈，不是语言性能排名，
也不代表优化后的生产服务能达到的固定延迟。
